# Backend (Google Apps Script)

This is the "brain": it stores your data, runs the reward rules, sends the
9pm/9am/Sunday emails, and handles login. It runs free on your Google account
and sends email from your Gmail natively (no app password, no SMTP).

`engine.js` + `engine.test.js` are the unit-tested reward logic (`node --test`
in this folder). `Code.gs` embeds that same logic plus storage, email, auth,
and triggers — it's the file you paste into Apps Script.

`Code.gs` is generated by `node build.js` from `main.gs` + `engine.js` — edit those instead.

## One-time setup (~10 minutes)

1. **Create the project**
   - Go to <https://script.google.com> → **New project**.
   - Name it "Habit Builder".

2. **Set the timezone**
   - ⚙️ **Project Settings** → **Time zone** → `America/Denver`.

3. **Paste the code**
   - Open `Code.gs` here, copy *all* of it, and replace the default
     `Code.gs` content in the editor.

4. **Edit the CONFIG block at the top of `Code.gs`:**
   - `ALLOWLIST` → your two real emails, lowercase.
   - `DASHBOARD_URL` → your GitHub Pages URL, e.g.
     `https://YOURNAME.github.io/YOUR-SITE-REPO/habits/`
     (the page must be reachable; trailing slash is fine).
   - There is **no** `SECRET` to fill in. The key that signs the one-tap email
     links is generated into Script Properties the first time it's needed, so it
     never lives in the code. (Upgrading from a version that had `var SECRET`?
     Set a `SECRET` Script Property to your old value **before** deploying, or
     the ✅/❌ buttons in already-sent emails will stop working.)

5. **Deploy as a Web app**
   - **Deploy** → **New deployment** → gear icon → **Web app**.
   - **Execute as:** Me. **Who has access:** **Anyone**.
   - Click **Deploy**, approve the permission prompts (Gmail, Sheets, Triggers).
   - Copy the **Web app URL** (ends in `/exec`).

6. **Wire the URL into the frontend**
   - Paste the `/exec` URL into `habits/js/config.js` (`WEB_APP_URL`).
   - It does **not** need to go back into `Code.gs`.

7. **Install the schedule + storage**
   - In the editor, choose the function **`setup`** in the toolbar dropdown →
     **Run**. Approve any remaining prompts.
   - This installs **one hourly `emailDispatch` trigger** (it decides each hour
     which categories are due for a reminder or a check-up, and rolls over
     freezes/bonuses), mints the email-signing key, and auto-creates the
     **"Habit Builder Ledger"** spreadsheet in your Drive.

8. **Verify**
   - Run **`runTests`** → open **View → Logs**, expect `ALL PASS ✅`.
   - Run **`emailDispatch`** once. It only emails categories whose
     `reminderTime`/`checkupTime` matches the *current* hour, so for an
     on-demand test set one of those to the current whole hour in the
     Categories admin UI first (weekly categories also only email on
     Sunday/Monday). Otherwise it does its refresh work and sends nothing —
     that's a pass, not a failure.

## Changing a rule later

Most rules (amounts, freeze counts, times) are per-category settings in the
Categories admin UI — no code change, no redeploy.

To change a *mechanic*, edit `engine.js` (reward logic) or `main.gs` (glue),
never `Code.gs`:

```bash
cd backend && node --test    # confirm the engine still passes
node build.js                # regenerate Code.gs
```

Then paste the new `Code.gs` into the editor and **re-deploy** (Deploy → Manage
deployments → edit → **New version**). A plain save is not enough for web apps.
The Web app URL stays the same.

See **Shipping a change** in [`../README.md`](../README.md) for the full flow,
including the ordering rule when a change touches both the frontend and the
backend.

## Notes

- **Schedules** fire in `America/Denver`. `emailDispatch` runs hourly and Google
  may run it anywhere within the hour, so a category set to `21:00` gets its
  email somewhere in the 9–10pm window; fine for reminders.
- **Data lives** in Script Properties (category settings, streak/freeze state,
  login tokens, the signing key) and the Ledger sheet (every entry/spend/bonus —
  wallets are derived from it). You can open the sheet anytime to audit.
- **Re-deploying** never loses data; it's all in your Google account.
